## 1. 一句話

**把腦中一直轉的那件事，分成「發生的事、對自己說的話、感受」，看見它怎麼繞回原點，再自己找到另一種看法和一個小步驟。**

方法依據是 CBT（認知行為治療）的 ABCDE 書寫法。使用者不需要知道 CBT。

## 2. Framing（a）

### 2.1 使用者打開時看到的開場

> 有一件事一直在腦中轉嗎？說給我聽，我陪你把它分開看。

開場不提 CBT，也不解釋流程。

### 2.2 開場下方的一行說明（可收合）

- 適合：某件**具體的事**之後，一直繞著同一個想法打轉
- 不適合：緊急狀況（附求助資源）、需要建議或診斷
- 你的地圖只存在這台裝置上（見 §7）

### 2.3 系統什麼時候會失效 → 決定 onboarding 怎麼寫

| 難處理的對話 | 為什麼會失效 | 回應方式 |
|---|---|---|
| 危機、自傷念頭 | 不該拿來「質疑想法」 | 開場就說明不是緊急工具；偵測到就顯示轉介卡、停止引導 |
| 想法其實是對的（失戀、親人過世） | 質疑想法等於否定感受 | AI 不走 D；只陪伴、命名感受、找一個照顧自己的小步驟 |
| 沒有具體事件，只是瀰漫的焦慮 | 找不到 A | 開場邀請「說一件今天讓你卡住的具體事」 |
| 只想發洩，或只想要建議 | 不想被引導 | 開場說明「這裡不給建議」；可以隨時停下 |
| 很多件事纏在一起 | 一張地圖塞不下 | 「我們一次看一件，你最想先看哪一件？」 |
| 生氣的對象是別人 | B 是對別人的想法 | 待測：B 也接受對別人的想法 |
| 回答很短、不配合 | 收集不到 ABC | 不硬逼；可以用目前有的內容直接到摘要 |

這張表也要放進報告，用來回答「framing」和「什麼時候會失效」兩個問題。

## 3. 機制：五個標籤（b）

### 3.1 標籤

原本的 ABCDE 合併 D 和 E，再加上我們自己的一步，總共五個：

| 標籤 | CBT | 使用者做什麼 | AI 做什麼 | AI 刻意**不**做什麼 |
|---|---|---|---|---|
| **A** 發生的事 | Activating event | 描述具體發生了什麼 | 問「那時發生了什麼？」 | 不安慰、不分析原因 |
| **B** 對自己說的話 | Belief | 說出當下腦中的想法 | 問「那時腦中閃過什麼？」 | 不判斷想法對錯 |
| **C** 感受 | Consequence | **自己**替感受命名：從兩個詞裡選，或寫自己的詞 | 問「那是什麼感覺？」，並給兩個不同方向的詞當選項（＋「我自己的詞」） | 不替使用者決定、不問「為什麼」 |
| **DE** 另一種看法 | Disputation + Effective new belief | 找證據、找別的解釋，寫出新的說法 | 邀請：「有什麼不太符合這個想法的？」「如果是朋友遇到，你會怎麼跟他說？」 | 不給答案、不說「往好處想」 |
| **Next step** 下一步 | （CBT 之外，我們加的） | 一個具體的小行動 | 問「什麼時候、做什麼？」 | 不指派任務 |

定義（報告時要講清楚）：

- **D** = 質疑那個想法：有證據嗎？有別的解釋嗎？
- **E** = 使用者自己得出的新說法
- **不是** positive thinking。CBT 要的是更準確，不是更正面。
- **Next step** 不是 CBT 的一部分，是我們加的，目的是讓一次的書寫變成行動。

**為什麼保留情緒選詞**（老師曾建議不要提供，報告時要說明理由）：

- 很多人卡住時說不出感受，只說得出「很煩」「很糟」。空白的「那是什麼感覺？」常常得不到答案。
- 兩個詞是鷹架，不是答案：方向不同（例如「慌」和「委屈」），使用者要比較、挑選，或寫出自己的詞，命名的動作仍然是使用者完成的。
- 研究依據：替情緒命名（affect labeling）本身有助於降低情緒強度；命名得越精確（emotional granularity），越容易調節。
- 這是報告中唯一保留的「選項」，因為它屬於機制本身，不是介面上的分支。

### 3.2 卡片規則（沿用 v2）

- 卡片只能是使用者原話的刪減（`trimmed()`），AI 不新增內容
- AI 不產生自己的卡片

### 3.3 什麼時候提議變成地圖

條件：A、B、C 都有，而且至少一張 DE。滿足後 AI 提議一次：

> 要不要把剛剛說的攤開來看？

- 「好」→ 進入地圖（§5）
- 「再聊一下」→ 下一則訊息後再提議一次
- 第 8 輪仍未滿足 → 用目前已有的內容提議
- 「That's enough for now」隨時可按 → 直接到摘要

## 4. 原型階段只留一條路（c）

**拿掉的分支**

| 拿掉 | 原因 |
|---|---|
| 「我自己排／幫我排」二選一 | 老師：原型只做一個決定。地圖一律走 §5.3 的引導流程 |

**保留，但不是報告重點的編輯功能**

自由拖拉、刪線、確認虛線、雙擊新增卡片、堆疊（×2）、改種類選單都保留。原則：

- 主流程（§5.3）不需要用到它們，累了的人只確認就能走完
- 報告時**不逐一介紹按鈕**，只在情境裡自然出現：「這時他發現⋯⋯，所以⋯⋯」
- 每個功能都要能說出它在什麼情境下有用：

| 功能 | 情境 |
|---|---|
| 確認／刪除虛線 | 「AI 以為是覺得丟臉才不傳訊息，但其實是先不傳訊息，越久越丟臉」→ 刪掉那條線，自己連反方向 |
| 自由拖拉 | 他想把「限動上的照片」放在最上面，因為一切從那裡開始 |
| 雙擊新增卡片 | 看著地圖，他想起漏講的一件事：「其實上週 Amy 還私訊問我最近好嗎」→ 補成一張 DE |
| 堆疊（×2） | 「他們其實沒那麼喜歡我」和「我是可有可無的那個」其實是同一個想法 → 疊在一起，看出它出現了兩次 |
| 改種類 | 「我覺得自己好可悲」被當成感受，但他發現那是一句對自己說的話 → 改成 B |

報告中最多示範一到兩個，例如堆疊和改種類，因為它們本身也在說明機制。

## 5. 第二部分：地圖（d）

### 5.1 核心想法

地圖上真正有治療意義的動作只有兩個：

1. **看見循環**：「原來我又繞回來了」
2. **自己決定從哪裡切斷**

所以：**位置由系統排，連線由使用者確認，切斷點由使用者選。**

### 5.2 Why / How / When finished

- **Why**：只有對話是線性的，看不出自己在繞圈。放到外面才看得見形狀。
- **How**：一次只亮一步，使用者只需要確認或修改。不用拖拉，累了也做得到；想自己調整的人，隨時可以用 §4 的編輯功能。
- **When finished**：使用者看見了循環，並選了一個切入點（DE 或 Next step 插進去）。之後顯示摘要。選「我還不確定」也算結束：看見循環本身就是一步。

### 5.3 流程

| 步驟 | 畫面 | 使用者做什麼 |
|---|---|---|
| 1 | A 卡出現 | 確認「這是發生的事」（可以編輯，只能刪字） |
| 2 | B 卡出現：「那時你是這樣對自己說的嗎？」 | 點「是」→ A→B 變成實線；「不是」→ 換一張 B 或跳過 |
| 3 | C 卡出現：「然後你覺得＿＿？」 | 確認 B→C |
| 4 | 用對話裡說過的話接回去：「覺得很丟臉之後，你就不想傳訊息給他們了，對嗎？」→「互動變少，下次就更不會被找。」 | 確認後線連回 A（或一張新的 A），**循環閉合**（動畫） |
| 5 | **先讓使用者看見循環**：「你有發現嗎？從沒被找開始，繞了一圈，又回到更不會被找。」 | 點「有」／「好像是」（說「不是」→ 打開那條線，讓他改） |
| 6 | **再邀請打破**：「如果要讓這個圈停下來，你會想從哪裡開始？」並給選項（見下方） | **選一個切入點** |
| 7 | 被選的那條線變淡或虛線，對應的 DE 或 Next step 卡插進去 | 確認，或用自己的話修改 |
| 8 | 摘要（§5.4） | — |

**第 6 步的選項**：每個選項是循環上的一條線，用使用者自己的話描述，並且對應到一種卡片。以「沒被邀請的聚餐」為例：

| 選項 | 切的是哪一條線 | 插入的卡片 |
|---|---|---|
| 換個方式看「他們其實沒那麼喜歡我」 | A → B（想法） | DE |
| 不再一直重看照片 | A → 重看照片（行為） | Next step |
| 主動傳訊息給其中一個人 | C → 不傳訊息（行為） | Next step |
| 我還不確定 | — | 不切，直接到摘要，地圖上留著循環 |

- 選項只從使用者已經說過的內容產生，AI 不提出新的解法
- 這也是在說明機制：切在「想法」叫換個看法（DE），切在「行為」叫做點不一樣的事（Next step）
- 選項之外，使用者也可以直接點地圖上的任何一條線

- 沒有循環時（第 4 步答「沒有」）：跳過第 5 步，第 6 步改問「哪一個想法你想換一種看法？」
- 有很多張 DE 時：第 7 步讓使用者選一張放進去，其他列在旁邊
- 「That's enough for now」任何一步都可以按 → 用目前已有的內容產生摘要

回應「行動卡加了，循環卻還在？」：循環**仍然看得到**，但被切開的那條線明顯斷了。意思是「我知道這個圈，也知道怎麼跳出來」。

### 5.4 摘要：用使用者自己的話做心理教育

方針：

- 開頭不教 CBT，過程中不解釋
- 在最後的摘要裡，**用使用者自己的卡片**說明今晚發生的事
- 只給一個帶得走的小工具
- 想知道的人才展開「這是什麼方法？」

註：CBT 的諮商師其實會解釋原理（psychoeducation），但會用個案自己的例子，而且在個案經歷過之後才說。這裡比照同樣的做法。

範例：

> **今晚的地圖**
>
> 在限動上看到朋友們一起吃飯，你沒被找（發生的事）→ 你對自己說「他們其實沒那麼喜歡我」（對自己說的話）→ 你覺得很丟臉（感受）→ 你不想傳訊息給他們，互動越來越少，又繞回「不會被找」。
>
> 你找到的另一種看法：「那天是 Amy 臨時約的，我那週說過很忙。」
> 你的下一步：這週傳訊息給其中一個人，約一頓飯。
>
> 很多人卡住，不是因為事情本身，而是因為中間那句對自己說的話。下次又開始繞的時候，可以先問自己：**我剛剛對自己說了什麼？**
>
> ▸ 這是什麼方法？（展開：CBT 與 ABCDE 的三行說明）

最後那句話回應了「最終目標是不是內化」：我們的立場是**希望使用者慢慢能自己問自己**，工具是練習的地方。

## 6. 報告結構

### 6.1 原則

- 整場只跟著**一個人的一個晚上**，每個畫面都是那個人的內容
- **用 demo 當解說**，不另外開理論投影片重講一次
- 時間分配：少講介面操作，多講介入機制和原因
- 主例子：§6.4「沒被邀請的聚餐」，整場 demo 都用它，也包含非線性時刻；備用的第二個例子：「主管的訊息」，時間夠才快速帶過，證明不只適用一種情境
- 隱私、framing 等問題要先帶著立場，再請教

### 6.2 骨架（約 12 分鐘）

| 時間 | 段落 | 內容 |
|---|---|---|
| 1 分 | 一個人、一個晚上 | 「週日晚上滑限動，看到朋友們一起吃飯，只有他沒被找，之後就一直睡不著。」 |
| 1 分 | 現有方法為什麼不夠 | 空白日記越寫越繞；聊天機器人只會安慰；CBT 表格要你先懂 CBT |
| 30 秒 | 一句話 | §1 |
| 1 分 | 五個標籤對照表 | §3.1，之後一直放在畫面角落當 legend |
| 4 分 | 對話 demo | §6.3，含 popup |
| 2.5 分 | 地圖 demo | §5.3，重點：循環閉合和切斷 |
| 1 分 | 第二個例子（備用） | 主管的訊息：快速帶過一張完成的地圖，證明換一種情境也成立 |
| 1 分 | 立場與問題 | framing（§2）、失效情境（§2.3）、隱私（§7），各帶暫定答案 |

### 6.3 Demo 模式（`/map?demo`）的修改

**標籤進度條**
- 畫面上方一排五格：A / B / C / DE / Next step
- 每蒐集到一個就亮起來，觀眾隨時知道進行到哪裡

**機制 popup**
- 每段 AI 回覆出現後，報告者再按一次，跳出 popup；看懂了再繼續
- 固定三行：
  1. **剛剛發生了什麼**：例如「使用者說了一件事，但還很模糊」
  2. **觸發的機制**：例如「要找 A（具體事件）」
  3. **AI 刻意做了什麼、沒做什麼**：例如「問『那時發生了什麼』；不安慰、不分析原因」
- 地圖階段也用同樣的 popup（循環閉合、選擇切斷點時）
- popup 只在 demo 模式出現，產品沒有。報告時要說一句。

**非線性時刻**
- 劇本裡至少安排一次：使用者沒回答問題、直接跳到感受
- popup 說明 AI 怎麼處理（先接住感受，之後再回頭找 A）

**穩定性**
- 地圖段落可預錄並加字幕，避免現場打字和說錯

### 6.4 Demo 例子

選擇標準：觀眾（學生、設計師）都經歷過；事件很小，但想法很大；有明顯的循環。

**例一（主例子，含非線性時刻）：沒被邀請的聚餐**

| 標籤 | 內容 |
|---|---|
| A | 在限動上看到朋友們週末一起吃飯，自己沒被找 |
| B | 「他們其實沒那麼喜歡我。」「我是可有可無的那個。」 |
| C | 第一句就先講感受；選詞 **left out** ／ **hurt** → 使用者寫自己的詞：「embarrassed」 |
| 循環 | 一直重看照片 → 不想傳訊息給他們 → 更少互動 → 下次更不會被找 |
| DE | 「那天是 Amy 臨時約的，我那週說過很忙。」「上個月是我主動約他們的。」 |
| Next step | 這週傳訊息給其中一個人，約一頓飯 |

非線性時刻（popup 要說明 AI 怎麼處理）：
1. 一開始就跳到感受：「我覺得自己好可悲。」→ AI 先接住感受，再回頭問「發生了什麼事？」
2. 中途要建議：「我要不要直接問他們為什麼沒找我？」→ AI 不給建議，把問題轉回來：「如果問了，你最擔心聽到什麼？」，這反而問出了 B
3. 選詞時不選，自己寫一個詞，說明使用者永遠可以用自己的話

切斷點：使用者選「主動傳訊息給其中一個人」，切在「覺得丟臉 → 不傳訊息」這條線。

**例二（備用，線性）：主管的訊息**

| 標籤 | 內容 |
|---|---|
| A | 晚上十一點，主管傳來「明天可以聊一下嗎？」，沒說是什麼事 |
| B | 「我一定做錯什麼了。」「她是不是對我很失望。」 |
| C | 選詞：**慌** ／ **羞愧** → 使用者選「慌」 |
| 循環 | 一直翻這週做過的東西、反覆看那則訊息 → 越看越覺得有問題 → 更慌，睡不著 |
| DE | 「上次她這樣傳，是要討論下個專案的排程。」「就算真的有地方要改，也不代表我做得很差。」 |
| Next step | 今晚回她「好，大概是關於什麼呢？」，然後就關掉電腦 |

切斷點：「反覆看訊息 → 越看越覺得有問題」這條線。

## 7. 隱私立場

這是能不能長期使用的門檻，不是附帶問題。

- **Local-first**：地圖只存在使用者的裝置上（現在已經是 localStorage）
- AI 只在當下對話時處理文字；原型使用 API，不另外保存對話
- 長期方向：本機模型，或可選擇完全不送出的模式
- 報告時先講這個立場，再問：「在這種條件下，你們會用嗎？還缺什麼？」

## 8. 之後要探索的（v3 不做）

### 8.1 跨對話的連結

- CBT 的觀點：一次的自動想法背後，常常是**反覆出現的核心信念**（例如「我不值得被愛」）
- 可能的價值：「你不是第一次這樣想；上次你是這樣走出來的。」
- 風險：需要保存資料（與 §7 衝突）；AI 說「你又這樣了」可能讓人覺得被評判
- 原則：AI 只提示相似；由使用者自己確認「對，這是同一個」

### 8.2 其他視覺化方式

- **CBT 的標準循環圖**（vicious cycle、五區塊模型：情境、想法、情緒、身體感受、行為）：用它當版型，比自由畫布更好懂，也更有引導
- **Obsidian 式的長期圖**：每晚一張小循環；重複出現的「對自己說的話」會變成越來越大的節點
- **視覺語言**：老師覺得太冷、太抽象。先決定系統的角色（陪伴者／教練／工具），再讓視覺跟著角色走

### 8.3 和現成 CBT 書寫表格的差別

需要一句話答案。暫定：表格要你先懂方法、自己填；這裡用對話把話引出來，再讓你**看見循環並親手切開**。
